Help

  • The draft is kept only for this tab, up to 2 MB. Reloading restores it; a new tab starts fresh. Light / dark applies to every tool.

Decode and encode

  • A new tab starts with a signed HS256 example. Generate example creates a fresh token and key for the selected algorithm.
  • Decode edits the encoded token; valid neighboring segments remain visible even if another part is invalid. Encode edits the JSON header/payload and signs automatically using the selected algorithm and key.
  • Red, purple and blue identify header, payload and signature. The signature status checks only the signature, not authorization, issuer or audience.

Keys

  • HMAC uses a shared secret as UTF-8, hex, Base64, Base64url or an oct JWK. Valid secret indicates the key meets the algorithm's minimum byte length; it does not prove randomness.
  • RSA, RSA-PSS, ECDSA and Ed25519 use JWK or PEM (SPKI public / PKCS#8 private). Encoding needs a private key. A private key can also verify, using its derived public key. Generated public keys are available below the key field.
  • Keys stay in this tab's session draft. Web Crypto needs HTTPS or localhost. An algorithm unsupported by the browser reports an error.

Validation and claims

  • Valid JWT means compact structure and strict JSON are valid. Signature Verified means the selected key verifies the signature. Neither establishes that the claims should be trusted.
  • exp, iat and nbf use Unix seconds. Time claims are shown in UTC. Duplicate keys, critical extensions and unencoded payloads cannot be signed or verified here.
